### Root Cause
When Code::Blocks creates a new GLUT project, it copies its template file from `C:\Program Files\CodeBlocks\share\CodeBlocks\templates\wizard\glut\files\main.cpp`.

By default, that template places `#include <stdlib.h>` **below** the GLUT headers:
```cpp
#ifdef __APPLE__
#include <GLUT/glut.h>
#else
#include <GL/glut.h>
#endif

#include <stdlib.h>
```

When `glut.h` is included before `<stdlib.h>` under MinGW-w64 on Windows, `glut.h` defines and subsequently `#undef`s internal C-runtime macros (`_CRTIMP`). When GCC later parses `<stdlib.h>` and `<corecrt_wstdlib.h>`, it fails to recognize `_CRTIMP`, throwing the compilation error:
`corecrt_wstdlib.h|15|error: '_CRTIMP' does not name a type`
