### Planner Response

### Root Cause
This error occurs in MinGW-w64 on Windows because `<GL/glut.h>` was included **before** the standard Windows and C-runtime headers (`<windows.h>` and `<stdlib.h>`).

When `glut.h` runs first, it defines low-level Win32 type macros prematurely. When `<stdlib.h>` (and `<corecrt_wstdlib.h>`) are included afterwards, GCC fails to recognize internal C-runtime macros like `_CRTIMP`, producing 50+ compilation errors.

---

### Solution

Move `#include <windows.h>` and `#include <stdlib.h>` to the **very top** of `main.cpp`, before including `<GL/glut.h>`.

#### Fix for `main.cpp`:
Replace the top includes in your `main.cpp` with the following:

```cpp
#include <windows.h>
#include <stdlib.h>

#ifdef __APPLE__
#include <GLUT/glut.h>
#else
#include <GL/glut.h>
#endif
```

### Planner Response

### Root Cause
Error **`0xc000007b` (`STATUS_INVALID_IMAGE_FORMAT`)** happens due to a **32-bit vs. 64-bit architecture mismatch at runtime**:

1. Modern Code::Blocks installs a **64-bit compiler** (`x86_64-w64-mingw32`), which compiles `lab-1.cpp` into a **64-bit executable file (`lab-1.exe`)**.
2. When `lab-1.exe` starts, Windows attempts to load `glut32.dll` (or `freeglut.dll`) from `C:\Program Files\CodeBlocks\MinGW\bin`.
3. However, `glut32.dll` is a **32-bit DLL**. 
4. Windows **cannot load a 32-bit DLL into a 64-bit application process**, causing Windows to terminate the program instantly with error `0xc000007b`.

---

### How to Fix It in Code::Blocks

#### Option 1: Compile as 32-bit in Code::Blocks (Quickest Fix)
Force Code::Blocks to build a 32-bit executable so it matches the 32-bit `glut32.dll`:

1. In Code::Blocks, top menu: click **Project > Build options...**
2. In the left panel, select your project name (e.g. `lab-1`).
3. Click the **Compiler settings** tab -> **Other compiler options** tab.
4. Add `-m32` in the text area.
5. Click the **Linker settings** tab -> **Other linker options** tab.
6. Add `-m32` in the text area.
7. Click **OK**.
8. Go to **Build > Rebuild** (`Ctrl + F11`), then press **`F9`** to run.

---

#### Option 2: Place a 64-bit `freeglut.dll` in your Project Output Directory
If you want to keep building 64-bit executables:

1. Download the **64-bit FreeGLUT binaries** package (e.g., from [Transmission Zero FreeGLUT for MinGW](https://www.transmissionzero.co.uk/software/freeglut-devel/)).
2. Extract the ZIP file and open the `x64` folder.
3. Copy `freeglut.dll` from the `x64` folder into your project's executable folder (e.g. `your_project_folder\bin\Debug\`).
4. Rename `freeglut.dll` to `glut32.dll` in that folder (if needed by your linker).
5. Run the project in Code::Blocks (**F9**).
